# 웹 게임 파티 자동 매칭 서비스 기능 명세서 종합본

## 0. 기능 분류 기준

본 명세서는 다음 3단계로 기능을 분류한다.

### 대주제

아키텍처에 배치된 5개의 애플리케이션 서비스다.

1. Core API + SSE 서비스
2. 즉시 매칭 서비스
3. 예약 매칭 RunTask
4. Notification Worker
5. Discord Worker

### 중주제

각 서비스가 담당하는 기능 영역이다.

예를 들어 Core API + SSE 서비스는 다음 기능 영역을 담당한다.

- 사용자 인증 및 계정 관리
- 사용자 프로필 및 Riot 계정 관리
- 매칭 요청 관리
- 파티 제안 및 수락 관리
- 확정 파티 관리
- SSE 실시간 상태 전달

### 소주제

각 중주제 기능을 실제로 구성하는 세부 기능이다.

예를 들어 `매칭 요청 관리`는 다음 세부 기능으로 구성한다.

- 즉시 매칭 요청 생성
- 예약 매칭 요청 생성
- 요청 입력값 검증
- 큐별 목표 인원 검증
- 요청 수정 및 취소
- 시간 중복 요청 차단

# 1. 서비스 범위 및 핵심 정책

## 1.1 서비스 범위

- 서비스는 웹으로만 제공한다.
- 네이티브 모바일 앱은 제공하지 않는다.
- 대상 게임은 리그 오브 레전드다.
- 리그 오브 레전드 한국 서버만 지원한다.
- 모든 일정과 시간 처리는 한국 표준시를 기준으로 한다.
- Discord OAuth2를 서비스 로그인 수단으로 사용한다.
- 자체 이메일·비밀번호 회원가입은 제공하지 않는다.
- Riot ID를 등록해 랭크 정보를 조회한다.
- 즉시 매칭과 일회성 예약 매칭을 제공한다.
- 알림은 서비스 화면의 SSE와 브라우저 Web Push로 제공한다.
- Discord 다이렉트 메시지는 선택 기능으로 제공한다.
- 파티가 최종 확정되면 Discord 전용 비공개 텍스트 채널을 생성한다.

## 1.2 파티 제안 단계의 대체 충원

파티 후보가 구성된 뒤 거절 또는 무응답자가 발생하면 제안 전체를 즉시 해체하지 않는다.

```text
최초 파티 후보 구성
→ 사용자들에게 동시 제안
→ 일부 수락, 일부 거절·무응답
→ 수락한 사용자는 현재 후보에 유지
→ 거절·무응답으로 생긴 빈 좌석만 대체 후보 탐색
→ 대체 후보에게 제안
→ 전체 좌석 수락 완료
→ 파티 최종 확정
```

- 한 번 수락한 사용자는 해당 제안이 최종 확정되거나 실패할 때까지 수락을 철회할 수 없다.
- 이미 수락한 사용자에게 대체 충원 후 다시 수락을 요구하지 않는다.
- 대체 후보가 다시 거절하거나 무응답이면 같은 좌석을 다시 충원한다.
- 전체 충원 제한시간 안에 정원을 채우지 못하면 제안을 최종 실패 처리한다.
- 최종 실패 시 기존 수락자는 최초 대기 순서를 유지한 채 다시 대기 상태로 돌아간다.

## 1.3 최종 확정 이후 정책

파티가 최종 확정된 이후에는 구성원을 변경하지 않는다.

- 파티 나가기 기능을 제공하지 않는다.
- 파티 확정 취소 기능을 제공하지 않는다.
- 파티 구성원 추가·제거·교체 기능을 제공하지 않는다.
- 최종 확정 후 빈자리 모집 기능을 제공하지 않는다.
- 실제 게임에 접속하지 않는 사용자에 대한 자동 대체 기능을 제공하지 않는다.
- 실제 플레이 종료 여부를 확인하거나 파티를 완료 상태로 변경하지 않는다.

## 1.4 예약 요청 묶음 정책

예약 매칭은 여러 후보 일정을 하나의 묶음으로 제출하고 그중 하나만 성립시킨다.

```text
사용자가 예약 후보 일정 N개를 하나의 묶음으로 제출
→ 묶음 내 요청끼리는 시간이 겹쳐도 허용
→ 당일 00시 배치가 묶음 단위로 처리
→ 조건을 만족하는 요청 중 우선순위가 가장 앞선 하나만 확정
→ 같은 묶음의 나머지 요청은 FAILED로 종결
```

- 하나의 묶음에서는 최대 하나의 파티만 확정한다.
- 묶음 내 요청 간 시간 중복은 허용한다. 어차피 하나만 성립하기 때문이다.
- 다른 묶음이나 이미 확정된 파티와의 시간 중복은 기존 규칙대로 차단한다.
- 묶음 내 우선순위는 사용자가 제출한 순서로 결정한다.
- 여러 요청이 동시에 성립 가능하면 우선순위가 앞선 요청을 채택한다.
- 묶음 전체 또는 개별 요청의 수정·취소는 예약 마감 이전에만 허용한다.
- 단건 예약 요청은 요청이 하나뿐인 묶음으로 취급한다.

# 대주제 1. Core API + SSE 서비스

## 서비스 책임

웹 클라이언트의 요청을 받아 사용자 계정, 프로필, Riot 계정, 매칭 요청, 파티 제안, 수락 상태와 확정 파티를 관리한다.

즉시 매칭 서비스가 만든 후보 파티를 사용자에게 제안하고, 거절·무응답이 발생하면 대체 충원을 요청한다. 모든 좌석의 사용자가 수락하면 파티를 최종 확정한다.

## 중주제 1.4 매칭 요청 관리

이 기능은 사용자 한 명이 보낸 요청 자체가 서비스 정책과 게임 규칙에 맞는지를 확인한다.

다른 사용자와의 호환 여부는 즉시 매칭 서비스 또는 예약 매칭 RunTask에서 판단한다.

| 소주제 ID | 소주제 | 설명 |
|---|---|---|
| 1.4.1 | 매칭 방식 선택 | 즉시 매칭 또는 일회성 예약 매칭을 선택한다. |
| 1.4.2 | 즉시 매칭 요청 생성 | 최대 대기시간과 예상 플레이시간을 포함한 즉시 요청을 생성한다. |
| 1.4.3 | 예약 매칭 요청 생성 | 날짜·시작 시각·시작 가능 범위·예상 플레이시간을 포함한 예약 요청을 생성한다. |
| 1.4.4 | 필수 입력값 검증 | 큐·인원·티어·포지션·음성·플레이 목적의 누락을 검사한다. |
| 1.4.5 | 입력값 형식 검증 | 잘못된 enum·날짜·시간·플레이시간 값을 거절한다. |
| 1.4.6 | 큐 선택 검증 | 솔로·듀오, 자유 랭크, 일반 중 하나의 큐만 선택하도록 한다. |
| 1.4.7 | 큐별 목표 인원 검증 | 선택한 큐에서 허용하는 목표 파티 인원인지 확인한다. |
| 1.4.8 | 자유 랭크 4인 차단 | 게임 규칙상 불가능한 자유 랭크 4인 요청을 거절한다. |
| 1.4.9 | 개인 신청 방식 제한 | 친구와 함께 신청하는 기존 파티 단위 요청은 지원하지 않는다. |
| 1.4.10 | 허용 티어 범위 검증 | 사용자가 본인 티어에서 선택 가능한 범위 안에서만 설정하도록 한다. |
| 1.4.11 | 솔로·듀오 이용 자격 검증 | 언랭크·배치 중·마스터 이상 사용자의 솔로·듀오 요청을 제한한다. |
| 1.4.12 | 대체 큐 안내 | 제한된 사용자에게 자유 랭크와 일반 큐를 안내한다. |
| 1.4.13 | 예약 날짜 검증 | 과거 날짜와 오늘 날짜의 예약 요청을 차단한다. |
| 1.4.14 | 예약 마감 검증 | 플레이 전날 23시 50분 이후 신규 예약과 수정을 차단한다. |
| 1.4.15 | 시작 가능 범위 검증 | 정확한 시각·앞뒤 30분·앞뒤 1시간 중 하나만 허용한다. |
| 1.4.16 | 예상 플레이시간 검증 | 서비스에서 정의한 플레이시간 값만 입력하도록 한다. |
| 1.4.17 | 시간 중복 요청 차단 | 기존 진행 요청이나 확정 파티와 시간이 겹치는 요청을 차단한다. |

# 6. 핵심 상태 구조

## 6.1 즉시 매칭 요청 상태

```text
CREATED
  → QUEUED
  → PROPOSED
  → REFILLING
  → CONFIRMED
```

실패 및 취소 분기:

```text
QUEUED → CANCELED
QUEUED → FAILED
PROPOSED → REFILLING
PROPOSED → CONFIRMED
REFILLING → CONFIRMED
REFILLING → FAILED
```

`CONFIRMED` 이후에는 사용자에 의한 상태 변경을 제공하지 않는다.

## 6.2 제안 참가자 상태

```text
PENDING
  ├─ ACCEPTED_LOCKED
  ├─ DECLINED
  └─ TIMED_OUT
```

- `ACCEPTED_LOCKED` 사용자는 파티가 확정되거나 최종 실패할 때까지 현재 후보에 유지된다.
- 수락을 철회할 수 없다.
- 거절·무응답 사용자는 현재 후보 파티에서 제거된다.

## 6.3 제안 좌석 상태

```text
PENDING
  ├─ ACCEPTED
  └─ OPEN
       → RESERVED
       ├─ ACCEPTED
       └─ OPEN
```

- 최초 제안 대상이 거절하거나 무응답이면 좌석이 `OPEN`으로 변경된다.
- 대체 후보를 선점하면 `RESERVED`가 된다.
- 대체 후보가 수락하면 `ACCEPTED`가 된다.
- 대체 후보가 거절하거나 시간초과되면 다시 `OPEN`이 된다.

## 6.4 예약 요청 상태

```text
RESERVED
  → MATCHING
  ├─ CONFIRMED
  └─ FAILED
```

예약 마감 전에는 다음 전이가 가능하다.

```text
RESERVED → CANCELED
```

예약 파티가 `CONFIRMED`된 이후에는 취소하거나 구성원을 변경하지 않는다.

묶음으로 제출된 예약은 다음과 같이 종결한다.

```text
묶음 내 한 요청이 CONFIRMED
  → 같은 묶음의 나머지 요청은 모두 FAILED
```
