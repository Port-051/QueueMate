# 멘토 요구사항 반영 — 2026-10-02

## 수동 모집 마감 · 시간 자동 마감 일시 중지 — 2026-10-03

최신 사용자 요청에 따라 시간 경과 자동 확정은 기본 비활성화한다. `platform.room.auto-confirm-enabled`는 `${ROOM_AUTO_CONFIRM_ENABLED:false}`로 읽으며 꺼져 있으면 새 마감 시각을 만들지 않고 기존 마감 시각도 API에서 null로 반환한다. 스케줄러 및 직접 호출되는 시간 자동 확정 검사도 실행하지 않는다. 기존 타이머 데이터는 삭제하지 않는다. 다시 true로 켜면 기존 만료 시각이 적용될 수 있다. 시간 연장 요청은 비활성 상태에서 409 `RECRUITMENT_NOT_EXPIRING`이다. 정원 충원 시 즉시 확정하는 동작은 유지한다.

모집 중인 게시판 방의 현재 방장에게 방 설정 바로 오른쪽에 아이콘·모집 마감 캡슐을 표시한다. 기존 확정 API의 최소 인원 조건에 맞춰 한 명일 때는 비활성화하고 이유를 툴팁으로 알린다. 두 명 이상이면 시간 안내 없이 언제든 누를 수 있다. 클릭하면 기존 방 나가기와 같은 확인창에서 현재 방 조건, 현재 멤버로 확정됨, 새 참가 불가·재모집 불가, 음성·채팅 유지 안내를 보여준다. 취소는 상태를 바꾸지 않는다. 확인은 기존 `session.confirm()`·확정 API를 사용하며 마감된 방과 일반 멤버에게는 버튼을 표시하지 않는다. 실패 시 팝업을 유지하고 재시도할 수 있다.


## P-54 방장 설정 수정 · 2026-10-03

사용자의 최신 요청으로 P-45의 수정 기능 삭제를 대체한다. 게시판 방의 현재 방장에게 음소거 버튼 바로 오른쪽에 40px 높이의 톱니바퀴·방 설정 캡슐을 표시한다. 방 만들기와 같은 폼을 현재 조건으로 채우며 저장 중 닫기·중복 저장을 막고, 실패하면 입력을 보존한다. 일반 멤버와 게시판 모집 글이 없는 빠른매치 전용 방에는 설정 버튼을 표시하지 않는다.

- `PATCH /api/v1/posts/{postId}`: 인증·Origin 검사는 기존과 같다. `PostCreateRequest`와 같은 전체 본문(`game`, `mode`, `title`, `voice`, `conditions`, `wantedPositions`, `hostPosition`, `allowAutoJoin`, 선택 `description`)을 받는다. 생략한 필드만 고치는 부분 수정은 아니다. 성공은 최신 `PostResponse` 200이다.
- 모집 중에는 제목·모드/인원·방장 포지션·찾는 포지션·마이크·빠른매치 입장 허용을 수정할 수 있다. 게임은 고정이며 정원은 해당 모드 설정으로 정한다. 모드 규칙이나 정원을 읽지 못하면 추측하지 않고 503으로 거절한다.
- 현재 인원보다 작은 정원, 다른 멤버가 쓰는 포지션의 제거·중복은 400으로 거절한다. 포지션 없는 모드로 바꾸려면 현재 다른 멤버의 포지션도 비어 있어야 한다. 다른 멤버의 포지션을 임의로 바꾸지 않는다. 정원을 현재 인원과 같게 줄이면 기존 확정 흐름으로 모집을 마감한다.
- 마감된 방은 제목·마이크만 수정할 수 있다. 모집 조건·설명 변경과 재모집은 막는다. 권한은 최초 글 작성자가 아니라 Redis의 현재 방장과 실제 멤버십으로 검사하므로 방장 승계 뒤에도 동작한다. 만료되거나 없어진 방에는 저장하지 않는다.
- 수정과 입장은 같은 글 행 잠금을 사용한다. 자동 합류는 후보를 고른 시점의 `updatedAt`과 잠금을 잡은 뒤의 값을 비교해 이전 조건으로 들어가지 않는다. `updatedAt`은 같은 밀리초 안에서도 증가한다.
- Redis Lua 한 번으로 현재 방장·멤버십·정원·포지션을 검사하고 방장 포지션과 남은 포지션을 갱신한다. 점유된 포지션은 남은 목록에서 빼며 기존 방 수명을 유지한다. 거절 시 Redis를 쓰지 않고 DB 트랜잭션도 롤백한다. DB 제약을 먼저 flush하지만 DB·Redis 사이에 분산 트랜잭션을 추가한 것은 아니다.
- 저장 커밋 뒤 `BOARD_CHANGED {}`를 발행한다. 목록과 열린 방은 조건을 재조회하고, 열린 방은 멤버 포지션도 새로 읽는다. 새로운 알림 종류나 DB 마이그레이션은 없다.
- 오류: 400 `VALIDATION_FAILED`(본문·정원·포지션·마감 제한), 403 `NOT_HOST`, 404 `POST_NOT_FOUND`/`ROOM_NOT_FOUND`, 409 `POST_NOT_RECRUITING`, 503 `ROOM_STATE_UNAVAILABLE`.
- 검증: 실제 PostgreSQL·Redis를 쓰는 `PostSettingsTest`에서 저장·권한·롤백·포지션 보존·정원 축소/자동 확정·방장 승계·동시 입장·오래된 자동 합류 후보를 확인한다. 브라우저에서는 방장 버튼 배치, 기존 값, 오류/저장 중 처리, 마감 제한, 일반 멤버 비노출, 모바일 화면을 확인한다. 실행 중인 미리보기 방에서도 기존 조건 그대로 저장 성공을 확인했다.


## 멤버 상세창 · 2026-10-03

- 방 목록과 방 안에서 여는 공통 상세창에 기존 사용자 아바타를 추가한다. 후속 축소 요청에 따라 창 너비는 300px, 안쪽 여백은 12px, 아바타는 40px이다. 닉네임·인증 아이콘을 첫 줄에, 포지션 캡슐·게임 닉네임을 둘째 줄에 배치한다. 잘린 이름은 툴팁으로 확인할 수 있다.
- LoL 최근 경기는 최신 요청에 따라 최대 10개를 한 줄의 원으로 표시한다. 승은 파랑, 패는 빨강이며 글자로도 구분한다. 표시한 10개에서 승패 합계를 계산한다. 경기 수가 적거나 커스텀이 제외되면 실제 기록 수만 표시하며 빈 기록을 임의로 채우지 않는다.
- `platform.riot.match-count` 기본값도 20에서 10으로 되돌린다. 평균 K/D/A·연승 역시 이 경기 목록으로 계산한다. 시즌 승패·숙련도 상위 챔피언·1시간 재수집 간격·커스텀 제외·실패 처리는 유지한다. 최대 Riot 호출은 24회에서 14회가 된다. 기존 스냅숏의 원형 승패 표시는 최신 10개로 제한하고 전적 평균은 다음 정상 동기화 때 갱신된다.
- 메시지 보내기·친구 추가·차단/차단 해제·신고는 아이콘이 있는 캡슐 버튼이며 두 열로 정렬한다. 이미 친구이면 같은 자리에 체크 아이콘과 비활성 `친구` 버튼을 표시하고, 요청을 보냈으면 `친구 요청 보냄` 상태를 표시한다. 차단 중에는 차단 해제가 보이고 친구 추가는 비활성화한다. 본인 상세에는 대인 작업 버튼이 없다. 방 목록과 방 내부의 규칙은 같다.
- 전적·버튼 사이 여백을 줄이고, 숙련도 높은 챔피언은 원형 사진·레벨을 한 줄에 나란히 배치한다. 챔피언 이름은 호버 시 확인한다. 내보내기의 맨 아래 오른쪽 별도 행을 유지한다. 창 너비는 300px이며 모바일 390px에서도 넘치지 않는다. 닫기 X는 24px 원형 버튼에 1px 테두리를 적용한다.
- 방장의 내보내기는 기존 권한과 확인창을 유지하며 맨 아래 오른쪽 별도 행에 배치한다. 상세창 아바타 색은 해당 방에서의 색과 일치시킨다.
- 인증 배지는 공통 `VerificationBadge`를 쓴다. 방 목록·방 내부·매칭 제안·참가 확인·상세·게임 프로필·온보딩·매칭 내 정보·방 채팅은 해당 게임의 `verified`를 사용한다. 친구/요청/차단/최근 플레이 목록과 개인 메시지/새 대화에서는 서버가 조회한 게임 계정 인증 여부를 사용한다. 인증되지 않았거나 조회에 실패하면 배지를 붙이지 않는다. 이름 옆에 같은 파란 아이콘과 툴팁을 표시한다.
- 검증: 프런트 타입 검사·빌드, `GameStatsSyncTest` 27개(최근 10경기 제한·평균·14회 호출·커스텀 제외), `VerificationApiTest` 3개(인증/미인증·익명 401·입력 제한). 독립 브라우저에서 목록·방·상세·참가 확인·프로필·친구·DM/새 대화의 배지, 인증 없는 계정, 10경기 한 줄, 원형 닫기와 모바일 390px 화면을 확인했다. 미리보기 예시 계정의 최근 기록만 10개로 갱신했다.

## P-52 모집과 확정

- 마지막 빈자리에 입장하는 Redis Lua 연산이 정원 검사·입장·확정을 원자적으로 처리한다. 마지막 입장은 종전대로 HTTP 201이다. `ROOM_MEMBER_ENTERED`와 `ROOM_CONFIRMED`가 전달되고 PostgreSQL에 확정 순간의 파티원·포지션을 저장한다.
- 확정된 글은 게시판에 남는다. 새 사람의 입장은 409 `POST_NOT_RECRUITING`(동시 요청이 이미 Lua에 들어갔다면 `ROOM_CONFIRMED`)이다. 기존 멤버의 재입장은 200이며, 자동 합류로 마지막 자리를 채운 요청도 재시도 시 현재 방을 반환한다.
- 두 명 이상인 모집 방의 인원 구성이 바뀌지 않으면 기본 10분 뒤 방장에게 안내 팝업과 연장·현재 인원 확정 버튼을 표시하고, 추가 60초 뒤 현재 인원으로 자동 확정한다. 한 명으로 줄면 타이머를 취소한다. 입장·퇴장·강퇴·접속 만료로 명단이 바뀌면 다시 계산한다. 수동 확정은 그대로 가능하다.
- 시간은 멘토가 숫자로 지정하지 않은 구현 기본값이다. `platform.room.auto-confirm-idle-seconds`(600), `auto-confirm-warning-seconds`(60), `auto-confirm-poll-ms`(1000)로 설정한다. `auto-confirm-enabled=false`로 스케줄러를 끌 수 있다. 타이머는 브라우저 대신 서버 스케줄러가 관리하며 화면은 서버의 마감 시각을 표시한다. 기존 방의 접속 만료 규칙도 적용되므로 모든 사람이 접속을 끊어 방이 먼저 만료되면 자동 확정 대상에서 제외한다.
- 글 응답에 nullable ISO-8601 UTC `autoConfirmAt`, `autoConfirmWarningAt`을 추가한다. 한 명이거나 확정·만료 상태면 null이다.
- `POST /api/v1/rooms/{roomId}/recruitment/extend`: 인증 쿠키, 본문 없음. 현재 방장만 경고가 시작된 뒤 마감 전에 연장할 수 있다. 성공 204. 다른 사용자 403 `NOT_POST_HOST`, 모집 종료 409 `POST_NOT_RECRUITING`, 안내 시간 밖 409 `RECRUITMENT_NOT_EXPIRING`, 없는 글 404 `ROOM_NOT_FOUND`. 연장 시 타이머를 처음부터 다시 계산하고 `BOARD_CHANGED {}`를 발행한다.
- 확인 작업은 글 행 잠금과 조건부 상태 변경으로 중복 실행을 막는다. Redis 확정 후 DB 기록이 실패하면 다음 주기에 복구를 시도한다. 외부 저장소의 동시 장애까지 원자적 분산 트랜잭션을 보장하지는 않는다.
- 확정 카드의 `members[].position`과 `host.position`은 확정 당시 값이다. 기존 파티 기록(마이그레이션 이전)은 값이 없어 null일 수 있다. 만료된 글은 종전대로 빈 멤버 목록이다. `wantedPositions`는 최초 모집 조건이며, 화면의 남은 포지션은 현재 멤버가 고른 포지션을 제외해 계산한다. 확정 상태의 카드·필터는 “모집 마감”으로 처리한다.
- V11: `recruit_posts.auto_confirm_at`, `party_members.position` 추가. 기존 데이터 파괴 없음.

## P-53 개인 메시지

모든 경로는 인증·기존 Origin 검사를 거친다. 사용자 ID는 숫자다. 자기 자신, 없는 사용자, 양방향 어느 쪽이든 차단한 상대는 404 `USER_NOT_FOUND`다. 다른 사람 사이의 대화는 조회할 수 없다.

| 요청 | 응답 |
|---|---|
| `GET /api/v1/messages` | 200 `[{user:{userId,nickname},lastMessage:{id,senderId,recipientId,text,sentAt}}]`. 최근 대화 100개, 최신순, 차단한 상대 제외 |
| `GET /api/v1/messages/{userId}?before={messageId}` | 200 `{user, messages, nextCursor}`. 두 당사자 사이의 최근 50개를 오래된 순서로 전달. 이전 페이지가 있으면 가장 오래된 ID를 nextCursor로 전달, 없으면 null |
| `POST /api/v1/messages/{userId}` | 본문 `{clientMessageId:UUID,text:string}`. 200 메시지 객체. 빈 내용·2000자 초과·UUID 누락은 400. 앞뒤 공백 제거. 같은 발신자·UUID·내용·수신자 재시도는 중복 저장 없이 같은 메시지를 반환. 동일 UUID의 다른 내용·상대는 409 `MESSAGE_RETRY_CONFLICT` |

- 저장 성공 후 두 당사자에게 `DIRECT_MESSAGE_RECEIVED {fromUserId:"상대 번호"}`를 전달한다. 내용은 알림에 싣지 않고 REST로 재조회한다. 브라우저는 연결 끊김에 대비해 화면이 보일 때 5초마다 보완 조회한다.
- V12: `direct_messages` 추가. 둘 중 한 명이 탈퇴하면 FK CASCADE로 양쪽 대화에서 삭제한다. 개인정보 페이지에 저장·보관·전달 동작을 명시한다.
- 방의 음성·채팅은 계속 WebRTC를 사용하며 서버에 저장하지 않는다. 개인 메시지만 PostgreSQL에 저장한다. 마이크 상태는 DataChannel로 전달하고, 발언 표시는 WebRTC 음량 통계로 계산한다. 녹음·재생 기능은 없다.

## 추가 UI 정리 · 2026-10-02 (최신 요청 우선)
