`feature/full-stack-integration`의 `5caaaeeb44d42ac4cb45348f017fe7348a5bc084`에서 분기했다. UI 참고는 `7ee7177294b064d01ecda6934a7ba6d5d65e8172`, 요구사항 근거는 2026-09-20 강진범 멘토링 녹취록이다. 사용자의 이번 요청(멘토 요구사항 전부 반영)에 따라 과거의 “자동 확정 없음”, “확정된 카드 포지션 null”, “개인 메시지 제거” 결정은 이 브랜치에서 아래 내용으로 바뀐다. 이전 결정 이력은 삭제하지 않는다.

## P-52 모집과 확정

- 마지막 빈자리에 입장하는 Redis Lua 연산이 정원 검사·입장·확정을 원자적으로 처리한다. 마지막 입장은 종전대로 HTTP 201이다. `ROOM_MEMBER_ENTERED`와 `ROOM_CONFIRMED`가 전달되고 PostgreSQL에 확정 순간의 파티원·포지션을 저장한다.
- 확정된 글은 게시판에 남는다. 새 사람의 입장은 409 `POST_NOT_RECRUITING`(동시 요청이 이미 Lua에 들어갔다면 `ROOM_CONFIRMED`)이다. 기존 멤버의 재입장은 200이며, 자동 합류로 마지막 자리를 채운 요청도 재시도 시 현재 방을 반환한다.
- 두 명 이상인 모집 방의 인원 구성이 바뀌지 않으면 기본 10분 뒤 방장에게 안내 팝업과 연장·현재 인원 확정 버튼을 표시하고, 추가 60초 뒤 현재 인원으로 자동 확정한다. 한 명으로 줄면 타이머를 취소한다. 입장·퇴장·강퇴·접속 만료로 명단이 바뀌면 다시 계산한다. 수동 확정은 그대로 가능하다.
- 시간은 멘토가 숫자로 지정하지 않은 구현 기본값이다. `platform.room.auto-confirm-idle-seconds`(600), `auto-confirm-warning-seconds`(60), `auto-confirm-poll-ms`(1000)로 설정한다. `auto-confirm-enabled=false`로 스케줄러를 끌 수 있다. 타이머는 브라우저 대신 서버 스케줄러가 관리하며 화면은 서버의 마감 시각을 표시한다. 기존 방의 접속 만료 규칙도 적용되므로 모든 사람이 접속을 끊어 방이 먼저 만료되면 자동 확정 대상에서 제외한다.
- 글 응답에 nullable ISO-8601 UTC `autoConfirmAt`, `autoConfirmWarningAt`을 추가한다. 한 명이거나 확정·만료 상태면 null이다.
- `POST /api/v1/rooms/{roomId}/recruitment/extend`: 인증 쿠키, 본문 없음. 현재 방장만 경고가 시작된 뒤 마감 전에 연장할 수 있다. 성공 204. 다른 사용자 403 `NOT_POST_HOST`, 모집 종료 409 `POST_NOT_RECRUITING`, 안내 시간 밖 409 `RECRUITMENT_NOT_EXPIRING`, 없는 글 404 `ROOM_NOT_FOUND`. 연장 시 타이머를 처음부터 다시 계산하고 `BOARD_CHANGED {}`를 발행한다.
- 확인 작업은 글 행 잠금과 조건부 상태 변경으로 중복 실행을 막는다. Redis 확정 후 DB 기록이 실패하면 다음 주기에 복구를 시도한다. 외부 저장소의 동시 장애까지 원자적 분산 트랜잭션을 보장하지는 않는다.
- 확정 카드의 `members[].position`과 `host.position`은 확정 당시 값이다. 기존 파티 기록(마이그레이션 이전)은 값이 없어 null일 수 있다. 만료된 글은 종전대로 빈 멤버 목록이다. `wantedPositions`는 최초 모집 조건이며, 화면의 남은 포지션은 현재 멤버가 고른 포지션을 제외해 계산한다. 확정 상태의 카드·필터는 “모집 마감”으로 처리한다.
- V11: `recruit_posts.auto_confirm_at`, `party_members.position` 추가. 기존 데이터 파괴 없음.

## P-53 개인 메시지

모든 경로는 인증·기존 Origin 검사를 거친다. 사용자 ID는 숫자다. 자기 자신, 없는 사용자, 양방향 어느 쪽이든 차단한 상대는 404 `USER_NOT_FOUND`다. 다른 사람 사이의 대화는 조회할 수 없다.

| 요청 | 응답 |
|---|---|
| `GET /api/v1/messages` | 200 `[{user:{userId,nickname},lastMessage:{id,senderId,recipientId,text,sentAt}}]`. 최근 대화 100개, 최신순, 차단한 상대 제외 |
| `GET /api/v1/messages/{userId}?before={messageId}` | 200 `{user, messages, nextCursor}`. 두 당사자 사이의 최근 50개를 오래된 순서로 전달. 이전 페이지가 있으면 가장 오래된 ID를 nextCursor로 전달, 없으면 null |
| `POST /api/v1/messages/{userId}` | 본문 `{clientMessageId:UUID,text:string}`. 200 메시지 객체. 빈 내용·2000자 초과·UUID 누락은 400. 앞뒤 공백 제거. 같은 발신자·UUID·내용·수신자 재시도는 중복 저장 없이 같은 메시지를 반환. 동일 UUID의 다른 내용·상대는 409 `MESSAGE_RETRY_CONFLICT` |

- 저장 성공 후 두 당사자에게 `DIRECT_MESSAGE_RECEIVED {fromUserId:"상대 번호"}`를 전달한다. 내용은 알림에 싣지 않고 REST로 재조회한다. 브라우저는 연결 끊김에 대비해 화면이 보일 때 5초마다 보완 조회한다.
- V12: `direct_messages` 추가. 둘 중 한 명이 탈퇴하면 FK CASCADE로 양쪽 대화에서 삭제한다. 개인정보 페이지에 저장·보관·전달 동작을 명시한다.
- 방의 음성·채팅은 계속 WebRTC를 사용하며 서버에 저장하지 않는다. 개인 메시지만 PostgreSQL에 저장한다. 마이크 상태는 DataChannel로 전달하고, 발언 표시는 WebRTC 음량 통계로 계산한다. 녹음·재생 기능은 없다.

## UI 및 출시 범위

- 이전 카드 UI에서 닉네임·티어·포지션·승률·KDA·주 챔피언 구성을 차용했다. 이후 사용자 밀도 조정 요청에 따라 게시판은 멤버당 34px 한 줄로 바꿨다. 데스크톱은 두 개의 5인 방을 한 화면에서 읽고, 좁은 화면의 부가 전적은 프로필에서 확인한다. 실제 전적이 없으면 임의의 수치를 채우지 않는다.
- 데스크톱은 게시판과 우측 방 패널을 함께 표시한다. 방 패널은 5개 좌석을 한 줄로 표시하고, 모든 게임의 상세 정보를 호버·키보드 포커스 또는 클릭 메뉴의 프로필에서 읽는다. 일반 모집 안내와 방 이용 안내는 접을 수 있고, 자동 마감 경고 팝업은 유지한다. 모바일은 기존 방 패널 전환 구조를 유지한다. 모집 중에도 음성·방 채팅을 사용할 수 있다. 닉네임 카드와 친구 목록에서 실제 개인 메시지로 이동한다.
- 방장·현재 발언자·마이크 꺼짐·음소거를 구분한다. 친구 카드는 이름과 부가 정보를 줄바꿈한다.
- 랜딩 H1·기능 H2·title·description·OG·Twitter에 롤 듀오와 5인 파티를 설명한다. robots.txt와 sitemap.xml은 저장소에 이미 사용하던 `https://queue-mate.com/` 도메인을 기준으로 작성했다.
- Search Console 소유권 인증·사이트맵 제출, 도메인/인증서 운영, SNS 계정 운영, 광고 집행은 코드 변경으로 완료할 수 없는 외부 운영 작업이며 이번 브랜치에서 수행했다고 주장하지 않는다. 실제 운영 도메인이 바뀌면 메타데이터와 사이트맵을 함께 수정해야 한다.
