# 16. 실시간·예약 모집 게시판

2026-09-13 사용자 승인: 실시간과 예약을 유지하며 홈에서 모집 목록, 직접 참여,
자동매칭, 모집 갱신과 조건 변경 제안을 제공한다. 이전의 공개 모집 금지 규칙을 대체한다.

## 사용자 흐름

- 홈: 게임 선택 → 실시간/예약 탭 → 조건 필터 → 10개 모집 행 → 상세/참여 패널.
- 2026-09-14 UI: 자기소개 작성, 모집 시작·타이머·조건 관리, 상세·참여 신청, 수락·파티 준비는 홈 오른쪽 내 정보 영역에서 이어진다. 별도 작성/상세 팝업과 본문 상단 모집 패널은 사용하지 않는다.
- 관리 동작은 개별 버튼으로 노출한다. 좁은 화면에서는 같은 영역을 목록 위에 배치하며, 제안 도착 시 작성 중인 초안과 상세 탐색 중 파티 연결을 유지한다.
- 모집: 기존 실시간 요청 또는 예약 하나와 모집 카드 하나를 연결한다.
- 직접 신청과 자동매칭은 같은 원본 요청을 사용한다. 자동매칭 참여는 명시적으로 선택한다.
- 신청 수락은 인원 모집 단계다. 정원이 모이면 기존 proposal을 만들고 전원 수락 후 Party를 만든다.
- 다인 모집의 참가자는 다른 자동매칭에 개별 배정되지 않는다. 대기 그룹을 유지한 채 남은 자리를 채운다.
- 채팅/음성/준비는 기존 Party를 재사용하고 페이지 이동에도 연결을 유지한다.

## 2026-09-14 비동기 1:1 수락 UX (프론트 미리보기)

최신 사용자 지시로 위의 `전원 수락 → 홈 파티` 흐름을 프론트에서 대체한다.
실제 서버 API와 기존 proposal/Party 계약은 이번 화면 작업에서 변경하지 않는다.

- 게임은 왼쪽에서 선택한다. 오른쪽에는 게임명을 반복하지 않는다.
- 자기소개·시작·타이머·조작은 오른쪽 영역에서 이어진다.
- 자동 매칭은 조건이 맞는 상대를 한 명씩 보여준다. 수동 매칭은 모집 상세에서 같은 `같이 할래요` 동작을 제공한다.
- 내 오케이를 보내도 모집은 OPEN이고 타이머와 목록 탐색을 유지한다. 서로 다른 여러 상대에게 동시에 오케이를 보낼 수 있다.
- 상대가 먼저 오케이해도 내 수락까지 기다린다. 먼저 서로 수락한 한 명과 성사되면 해당 모집을 마감하고 같은 모집의 나머지 제안을 취소한다.
- 성사 알림과 시스템 메시지를 만들고, 사용자가 메시지로 이동해 텍스트·음성 대화를 이어간다. 홈에서 강제로 이동하지 않는다.
- 취소·멈춤·조건 변경·만료·차단 이후의 늦은 응답, 중복 응답은 매칭을 성사시키지 않는다.
- 실시간·예약에 동일한 수락 흐름을 적용하며 예약 시간 조건을 유지한다.
- 미리보기는 자동 후보 탐색 6초, 예시 상대 응답 20초를 사용한다. 화면을 이동해도 응답 처리를 계속한다. 오케이 상태는 기존 mock 모집처럼 세션 메모리에만 보존하며 메시지·알림은 기존 로컬 저장을 사용한다.
- 실제 서버의 동시성·이벤트 전달과 실제 음성 연결을 검증한 것으로 간주하지 않는다. 서버 연동 시 양측 원본의 상태·조건·차단 재검증과 원자적 확정이 필요하다.

## 조건

기존 MatchCondition(게임/모드/본인 포지션·역할·스타일/음성/목적)에 모집 선호를 연결한다.
본인 티어, 상대 최소/최대 티어, 원하는 상대 포지션·역할·스타일, 목적 필수 여부를 추가한다.
본인 티어를 직접 입력한 경우 SELF_REPORTED로 표시한다. 외부 인증 티어처럼 표시하지 않는다.
티어 미입력은 티어 범위를 지정한 상대의 조건을 통과하지 않는다.
양쪽의 상대 조건과 기존 hard rule, 차단, 인원, active proposal을 모두 확인한다.
예약은 공통 30분 시작 슬롯과 같은 플레이 양을 추가 확인한다.
검색 조건은 내 모집 조건을 자동 변경하지 않는다.

## 생명주기

- 최초 시작, 모집 확인, 끌어올림, 마지막 노출 시각은 별도로 보존한다.
- 실시간은 마지막 확인 10분 뒤 재확인 안내, 12분 뒤 숨김. 예약은 오프라인으로 숨기지 않는다.
- 첫 개선 제안은 등록 3분 뒤. 끌어올림 재사용 간격은 5분이다. 초기 실험값이며 설정으로 조정한다.
- CONFIRM은 의사만 확인하며 순위를 올리지 않는다. BUMP는 확인+노출 갱신이다.
- PAUSE/RESUME/CLOSE를 제공한다. 참가자·제안 진행 중에는 조건 편집을 제한한다.
- 예약은 시작까지 30분 이내일 때 재확인을 제안하고 종료 시간이 지나면 만료한다.
- 끌어올림은 새 모집으로 집계하지 않는다. 후보 적합도 안에서 노출 기회를 순환한다.

## 제안과 필터

- 필수 조건과 활동 확인 통과 → 선호 일치 → 갱신 이후 노출이 적은 모집 → 최근 갱신.
- 목적/상대 포지션/상대 티어 범위/음성 중 한 항목만 변경한 후보군을 다시 계산한다.
- 상대의 조건도 충족하는 실제 후보가 늘 때만 제안을 제공한다. 성공 확률은 표시하지 않는다.
- 미리 보기와 적용을 분리한다. 적용 시 최신 상태와 version을 다시 검증한다.
- 게임/모드/차단/시간/정원 등의 시스템 제한은 조건 변경 제안으로 우회하지 않는다.
- 새로운 목록 순서는 사용자가 갱신할 때 반영하되 마감/상태 변경은 즉시 반영한다.

## 저장과 API

`recruitments`는 기존 sourceId에 연결되는 모집 메타데이터다. 별도의 매칭 대기열을 만들지 않는다.
한 원본은 모집 하나만 갖는다. 신청/참가 연결도 원본을 재사용한다.
`contracts/recruitment.openapi.yaml`이 신규 API의 정본이며 main OpenAPI에서 참조한다.
모집 쓰기는 소유권, version, 상태를 검증한다. 정원 확정은 기존 Redis claim과 DB 제약을 거친다.
RECRUITMENT_UPDATED는 데이터 없는 게시판 무효화 알림이다. 민감한 조건/신청자는 broadcast하지 않는다.
재연결/포커스 복귀에는 최신 스냅샷을 조회한다. 읽기 실패를 후보 0으로 표시하지 않는다.

## 지표

모집 생성, 고유 노출, 끌어올림, 확인, 일시중지, 신청, 수락/거절, 조건 제안/적용,
proposal, 양측 준비 완료를 기록한다. 실시간 최초 시작시각과 예약 약속시각을 구분한다.
실시간 10분 내 준비율과 예약 약속시각 준비율은 별개다. PLAYING 추정을 실제 게임 시작으로 집계하지 않는다.

## 검증

- 양방향 포지션/티어, 미입력 티어, 음성 불일치, 차단, 만료, 예약 교집합.
- 검색이 내 조건을 바꾸지 않음, 단일 조건 변경, stale version 거부, bump cooldown.
- 직접 참여/자동매칭 경쟁, 정원 초과, 중복 신청/참가, 전원 수락 이전 Party 생성 금지.
- 실시간 숨김과 예약 오프라인 유지, 다인 그룹 모집, 실패 후 복귀, 재접속 복구.
- 실제 REST/DB/Redis 통합 테스트와 mock UI E2E를 구분해서 실행한다.

구현·실행·관측의 한계와 검증 방법은 [17. 모집 게시판 구현과 검증](17_RECRUITMENT_IMPLEMENTATION.md)을 따른다.
