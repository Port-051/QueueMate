# 같은 방을 찾는 두 경로 — 빠른 연결 UI

2026-09-23 세컨 브레인 `me/경험/QueueMate_매칭후보_통합합의.md`의 최신 합의를 기준으로 한다.
강진범 멘토의 피드백은 초기 사용자를 분리하지 않고 같은 방을 직접 탐색 또는 빠른 연결로 찾는 구조다.
이 문서는 기존 방 카드 데모에 추가한 UI 범위이며, 서버 계약을 변경하지 않는다.

## 이번 구현

- 실시간 홈 첫 영역에서 내 포지션·역할·스타일과 마이크를 선택하고 방을 제안받는다.
- 별도 큐나 사용자 풀을 만들지 않는다. `useRoomStore`의 같은 방 객체를 직접 탐색과 빠른 연결에 사용한다.
- 현재 게임·모드, 빈자리, 모집 상태, 방의 원하는 역할과 내 역할, 마이크 상충을 확인한다.
- 적은 빈자리 우선, 동일 빈자리면 최신 생성 순으로 한 방씩 제안한다. 성공 확률이나 AI 점수는 표시하지 않는다.
- 자유서술 조건을 충족한다고 단정하지 않는다. 방 상세에서 제목과 멤버 한마디를 읽고 사용자가 입장을 선택한다.
- 입장 직전 현재 방 조건을 다시 확인하며, 기존 단일 방 참여·정원 검사와 대화 UI를 재사용한다.
- 목록은 기본적으로 모집 중인 방을 보여주며, 체크를 해제하면 확정된 방도 볼 수 있다.
- 목록의 탐색용 필터는 빠른 연결의 내 역할·마이크를 변경하지 않는다. 게임·모드 변경 시 제안 상태를 초기화한다.
- 후보가 없거나 모두 넘겼다면 조건 재선택 또는 내 방 만들기를 제공한다. 무한 로딩·가짜 예상 시간은 표시하지 않는다.

## 검증과 남은 범위

- `npm run build`
- `npx playwright test --config tests/playwright.config.ts`: 브라우저 없이 후보 선택 규칙 7개 테스트.
- 내장 브라우저: 역할 선택, 추천, 상세, 입장 후 대화 영역, 나가기, 후보 없음, 화면 폭 390px 및 1600px 확인.
- 기존 `HomePage`의 mock 전용 분기를 유지한다. 실서버 홈, REST/이벤트 계약, 실제 음성 통신을 변경하지 않았다.
- 데모의 방 입장/정원 확정은 기존 로컬 동작을 재사용한다. 운영 환경의 양측 동의·차단·동시성 검증을 구현한 것으로 보지 않는다.
- 서버 연동 전 방장의 빠른 연결 참여 동의, 자유서술 조건 확인/승인 흐름, 차단 관계, proposal 불변식과 원자적 입장을 계약에 명시해야 한다.
- 예약 시간 적합성, 다인 방의 빈자리 자동 충원, 페이지 이동 후 연속 탐색은 후속 범위다.
