# 방 카드 덱 UI 데모

2026-09-21 사용자 요청으로 프론트 홈을 개인별 듀오 목록에서 방 단위 탐색으로 확장했다. `docs/16_RECRUITMENT_BOARD.md`의 기존 1:1 화면과 서버 계약은 실 API 화면에서 유지된다.

## 실행 범위

- `cd frontend && npm ci && npm run dev:mock`: 새 방 카드 화면. 기본 LoL 일반 모드로 여러 명이 참여한 방을 보여준다.
- `VITE_HOME_LAYOUT=legacy npm run dev:mock`: 이전 개인별 매칭 화면을 그대로 확인할 수 있다.
- `npm run dev` / `npm run dev:mock-server`: 기존 API와 연결하는 개인별 화면. 그룹 방 API를 흉내 내어 서버로 보내지 않는다.
- 새 방 데이터와 채팅은 사용자 ID별 `qm:room-board:v1:<userId>`에 저장한다. 같은 브라우저·동일 계정의 탭 간에는 갱신되지만 다른 팀원이나 기기와 공유되는 서버 데이터가 아니다.
- 음성 참여·음소거·듣기 끄기는 미리보기이며 실제 마이크나 상대방과 연결하지 않는다. 기존 음성 모듈의 Mock 클라이언트만 사용한다.

## 화면과 상태

- 기본 목록은 세 열의 방 카드 덱이다. 평균 티어·승률·KDA, 참여자의 포지션, 찾는 포지션, 마이크, 현재/정원 인원을 보여준다.
- 덱 선택 시 원래 위치에서 중앙으로 이동한 뒤 요약 카드와 개인 카드가 펼쳐진다. 전체 카드 묶음을 중앙 정렬한다. 작은 화면은 카드 영역 안에서 가로로 스크롤한다.
- 카드 접기/Escape/배경 클릭으로 돌아간다. 키보드 포커스는 연 방으로 복귀하며, 모션 감소 설정이면 이동 애니메이션을 생략한다.
- 실시간과 예약 모두 방 생성·입장 즉시 목록은 한 열이 되고 오른쪽 대화 영역이 열린다. 작은 화면에서는 대화 영역을 목록 위에 놓는다.
- 방장은 팀원을 내보내거나 2명 이상인 방을 정원 전에 확정할 수 있다. 마지막 자리가 채워지면 자동으로 확정된다.
- 확정된 방은 회색으로 남고 내부 정보를 확인할 수 있지만 입장은 막힌다. 기존 참가자는 계속 대화할 수 있다. 누군가 나가거나 내보내져도 자동으로 모집을 재개하지 않는다.
- 한 사람은 한 방만 참여한다. 방장이 나가면 남은 첫 참가자에게 방장을 넘기고, 마지막 사람이 나가면 빈 방을 제거한다.
- LoL 랭크는 최대 2명, LoL 일반·신속·칼바람과 발로란트는 최대 5명, 배틀그라운드 듀오는 2명·스쿼드는 4명이다. 칼바람에는 고정 포지션을 표시하지 않는다.
- 예약은 미래의 30분 단위 시작 시간을 선택한다. 방의 채팅은 예약 시각 전에도 쓸 수 있다.

## 요약 계산

- 승률과 KDA는 유효한 수치를 가진 참가자의 단순 산술평균이다. 경기 수로 가중한 팀 전체 승률이 아니다.
- 티어는 각 게임의 티어·단계를 순서대로 놓고 평균 위치를 가장 가까운 단계로 반올림한다. 실제 MMR이나 랭크 대기열 참여 가능 여부를 나타내지 않는다.
- 누락된 값은 평균에서 제외하고, 전부 누락되면 `—`로 표시한다.
- 포지션은 참여자의 선택을 합쳐 정해진 순서로 표시한다. 모든 포지션을 선택한 경우 ALL 아이콘으로 요약한다.

## 검증 및 다음 서버 작업

`npm run build`, `npx playwright test --project=room-decks`로 새 UI를 검증한다. 기존 흐름은 별도 포트의 `legacy` 환경에서 `--project=chromium`으로 검증한다.

실서비스 연결 전에는 그룹 방 생성/입장/퇴장/강퇴/확정 API, 동시 입장의 정원 제어, 권한·차단 관계·게임별 랭크 제한, 메시지 저장/이벤트, WebRTC 시그널링 계약이 필요하다. 현재 UI의 로컬 상태를 서버 권한 검증이나 실제 매칭 결과로 사용하지 않는다.
