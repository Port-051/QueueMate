# QueueMate 검색어·등록·측정 실행안

조사일: 2026-09-28. 이 문서는 실행 준비용입니다. 검색엔진 등록 완료나 검색량 측정 결과가 아닙니다.

## 1. 담당 범위와 현재 조건

회의에서 요청한 범위는 기존 UI 톤을 반영한 별도 랜딩, 이용자 검색어 조사, 본문·메타정보, robots/LLM 안내, 성능·접근성 개선, 검색엔진 등록입니다. 유료 광고 집행과 SNS 영상 제작은 이 문서의 실행 범위에서 제외합니다. 회의의 요청과 아래 공식 문서 검증 결과는 구분합니다.

대표 도메인은 `q-mate.com`, 앱 연결 예정 주소는 `app.q-mate.com`입니다. 구매·DNS 연결·앱 출시가 완료됐다고 가정하지 않습니다. `allowIndexing=false`, `appReady=false`인 동안 검색 유입 성과를 기대하거나 앱 이용이 가능한 것처럼 홍보하지 않습니다.

## 2. 실제로 확인한 것과 확인하지 않은 것

`롤 듀오 구하기`, `롤 듀오 찾기`, `발로란트 파티 찾기`, `배그 스쿼드 구하기`를 검색해 관련 서비스·가이드의 제목과 문맥을 확인했습니다. DUO.OP.GG의 제목은 `롤 듀오 찾기`이고 실제 팀원 모집 화면으로 이어집니다.[1] 다른 게임의 검색 결과에는 파티·스쿼드 모집 표현이 등장했으나 일부 원문 조회가 실패했으므로 여기서는 구체적인 수요 근거로 사용하지 않습니다.

**검색 결과가 존재한다는 사실은 월간 검색량, 국내 점유율, 키워드 난이도 또는 상위 노출 가능성의 측정이 아닙니다.** Google Ads 키워드 플래너·네이버 광고 키워드 도구·Search Console의 계정 데이터에는 접근하지 않았습니다. 검색량과 CPC는 미측정으로 남깁니다. 검색 결과의 이용자 닉네임·모집글 내용은 수집하거나 복제하지 않았습니다.

## 3. 우선순위와 페이지 배치 — 제안

다음 우선순위는 검색량 순위가 아니라 현재 랜딩과 기능 설명의 적합성에 따른 작업 순서입니다.

| 우선순위 | 검색어 후보 | 방문 의도 | 배치/실행 |
|---|---|---|---|
| 1 | 롤 듀오 찾기, 롤 듀오 구하기 | 함께 플레이할 사람 찾기 | 홈페이지 제목·첫 설명·이용 방법에 자연스럽게 반영 |
| 1 | 큐메이트, QueueMate, q-mate | 브랜드 확인 | 사이트 이름·제목·푸터를 일관되게 유지 |
| 2 | 롤 파티 찾기 | 여러 명의 파티 구성 확인 | 기존 모집방 예시와 이용 흐름 설명 |
| 2 | 롤 듀오 마이크, 롤 듀오 포지션 | 조건이 맞는 팀원 찾기 | 조건 설명과 FAQ 후보; 별도 수요 측정 필요 |
| 3 | 발로란트 파티 찾기, 발로란트 듀오 찾기 | 해당 게임의 팀원 찾기 | 실제 공개 기능과 고유 화면이 준비될 때 전용 콘텐츠 검토 |
| 3 | 배그 스쿼드 구하기, 배그 같이 할 사람 | 해당 게임의 팀원 찾기 | 실제 공개 기능과 고유 화면이 준비될 때 전용 콘텐츠 검토 |

`듀오`만 쓰면 다른 의도가 섞일 수 있으므로 게임명을 포함한 표현을 우선합니다. 대리·계정 거래·승률 보장·강의 의도는 서비스 범위 밖이라 타깃 문구에서 제외합니다. 띄어쓰기 변형마다 복제 페이지를 만들거나 같은 단어를 과도하게 반복하지 않습니다. Google은 모든 표현 변형을 정확히 반복할 필요가 없으며 키워드 채우기를 피하라고 안내합니다.[2]

## 4. 사용할 수 있는 문구 초안

현재 사이트에 자동 적용한 변경은 아닙니다. 출시 범위 검토 후 선택합니다.

**제목:** 롤 듀오 구하기·파티 찾기 | 큐메이트 QueueMate

**설명:** 롤 듀오와 함께할 파티를 찾는 큐메이트입니다. 티어·포지션·마이크 조건과 모집방의 빈자리를 확인하고, 한 페이지에서 대화하며 게임을 준비하는 서비스를 만들고 있습니다.

**첫 화면 설명:** 같이할 사람을 찾느라 여러 글과 채팅방을 오가지 않도록. 원하는 조건을 확인하고, 파티를 구성하며, 같은 화면에서 대화를 이어가는 큐메이트를 준비하고 있습니다.

**공개 전 버튼:** 화면 먼저 살펴보기

**추가 FAQ 후보:**

- 지금 회원가입하거나 실제 팀원을 찾을 수 있나요? → 현재 소개 페이지의 모집방과 대화는 화면 예시입니다. 실제 이용 가능 여부는 서비스 공개 시 안내합니다.
- 어떤 조건을 확인할 수 있나요? → 준비 중인 화면에서는 티어, 포지션, 마이크 사용 조건과 파티의 빈자리를 확인하는 흐름을 보여줍니다. 실제 제공 조건은 공개되는 서비스 기준입니다.
- 별도의 채팅 프로그램을 설치해야 하나요? → 웹에서 모집과 대화를 이어가는 구성을 준비하고 있습니다. 실제 지원 브라우저·기기와 음성 기능은 출시 검증 후 안내합니다.

존재하지 않는 이용자 수, 매칭 성공률, 최저 대기 시간, 추천 후기 또는 인증된 전적을 넣지 않습니다. `트롤 없는 매칭`, `무조건 빠른 매칭`, `100% 성공`도 보장 문구로 사용하지 않습니다.

## 5. 검색 등록 준비표

| 서비스 | 공식 절차에서 확인한 내용 | 준비된 것 | 실제로 남은 것 |
|---|---|---|---|
| Google Search Console | 도메인 속성은 DNS 소유 확인. URL-prefix 속성은 HTML 메타태그 등 선택 가능.[3] | `verification.google` 입력 자리 | 도메인 구매·권한 확인, 실제 발급값 적용·검증, 사이트맵 제출 |
| 네이버 서치어드바이저 | 사이트 추가·소유 확인 후 수집/색인 보고서 활용. 메타태그는 최초 HTML head에 있어야 함.[4] | `verification.naver` 입력 자리, 정적 HTML | 로그인 없이 대표 주소 접속, 발급값 적용·소유 확인, 사이트맵 제출[5] |
| Bing Webmaster Tools | 직접 추가·검증 또는 검증된 Search Console 속성 가져오기 가능.[6] | `verification.bing` 입력 자리 | 계정 소유자 선택, 메타태그 등 검증 또는 가져오기 승인, 사이트맵 제출[7] |
| Daum 검색등록 | URL·등록정보 입력, 동의, 검토를 거치는 사이트 검색 등록 서비스.[8] | 사이트명·주소·설명 초안 | 실제 공개 사이트 확인, 소유자 정보와 동의, 업종별 제출서류 해당 여부 확인 후 신청 |
| ZUM | 공식 고객센터와 검색 문의 메뉴 확인. 기존 `/submit` 주소는 페이지 없음으로 표시됨.[9] | 확인 경로 기록 | 현재 신규 사이트 신청 경로를 고객센터에서 확인. 완료로 표시하지 않음 |

회의에서 MS와 Bing이 함께 언급됐더라도 이 실행표에서는 하나의 Bing 항목으로 관리합니다. 신청/소유 확인/수집/색인/검색 유입은 서로 다른 완료 상태입니다. 네이버는 사이트 등록 자체가 검색 노출의 필수 조건은 아니라고 명시합니다.[4]

입력용 기본 정보:

- 사이트명: 큐메이트 (QueueMate)
- 대표 주소: `https://q-mate.com/`
- 사이트맵 예정 주소: `https://q-mate.com/sitemap.xml` — 현재 noindex 빌드에는 생성하지 않음
- 소개: 게임 팀원과 파티를 찾는 서비스의 소개·이용 안내
- 담당 이메일/연락처: 소유자가 사용할 공식 값을 지정해야 함; 개인 정보를 추측해 제출하지 않음

소유 확인용 문자열은 각 계정에서 발급받은 값을 그대로 사용합니다. 빈 값을 가짜 코드로 채우지 않습니다. Search Console DNS 검증과 네이버 메타태그 검증을 혼동하지 않습니다.

## 6. 공개 직전 순서와 통과 조건

1. 기존 랜딩 프로젝트에서 로그인하지 않은 사용자의 접속을 허용하고 실제 랜딩이 200으로 열리는지 확인합니다. Vercel 로그인 화면의 200을 성공으로 처리하지 않습니다.
2. 구매가 확인된 도메인을 해당 랜딩 프로젝트에 연결합니다. 안내된 DNS 값을 사용하고 다른 TXT/MX 레코드를 삭제하지 않습니다. www를 대표 주소로 이동시킵니다. 앱 서브도메인은 앱 담당자와 별도 연결합니다.
3. 문구 검토 후 `contentApproved`, `uiApproved`, `allowIndexing`을 의도적으로 변경하는 공개 PR을 만듭니다. 현재 기본값을 고정하는 테스트도 공개 정책에 맞게 갱신합니다. `appReady`는 실제 앱 검증 전까지 false입니다.
4. Production으로 재빌드하고 아래 검사를 통과한 뒤 사이트맵을 제출합니다. 임시 호스트의 noindex는 유지합니다.

```sh
cd landing
npm run check:url -- https://q-mate.com production launch-check.json
```

대표 주소의 응답은 200 HTML, 올바른 canonical과 공개 가능한 robots 지시문, 실제 sitemap XML이어야 합니다. 존재하지 않는 경로는 진짜 404여야 합니다. 검색로봇이 noindex를 읽게 하려면 robots.txt로 수집 자체를 막지 않아야 합니다.[10]

## 7. 공개 후 첫 2주 측정 — 운영 제안

최초 등록일·소유 확인일·색인 확인일·제목 변경일을 구분해 기록합니다. 첫 수집/색인 여부를 확인하고, 주 단위로 동일 기간의 국가(대한민국), 기기, 검색어, 페이지별 노출수·클릭수·CTR을 비교합니다. 브랜드 검색과 일반 게임 검색을 따로 봅니다. Search Console은 해당 실적과 검색어·페이지·국가 구분을 제공합니다.[11]

| 상황 | 다음 확인 |
|---|---|
| 수집 자체가 안 됨 | 로그인 보호, robots, HTTP, 소유 확인과 사이트맵 |
| 수집됐지만 색인 제외 | noindex, canonical, 내용 부족/중복, 검색엔진 진단 사유 |
| 노출은 있으나 클릭이 적음 | 실제 검색어 의도와 제목·설명·경쟁 결과의 적합성 |
| 클릭은 있지만 앱 이용으로 연결 안 됨 | 앱 공개 여부·버튼 동작·전환 측정 설계; Search Console 클릭을 매칭 성공으로 세지 않음 |

처음에는 추적 스크립트 없이 검색엔진 보고서로 검색 유입을 확인합니다. 앱 전환 측정이나 광고 픽셀은 측정 목적·수집 범위를 정한 후 별도 변경으로 진행합니다. 주간 수치를 매일 바뀌는 작은 표본만 보고 성공/실패로 단정하지 않습니다.

## 8. 회의 요청을 구현할 때의 기술적 보완

태그 종류나 글자 수를 늘리는 것 자체를 목표로 삼지 않습니다. 내용에 맞는 제목 구조·목록·이미지 설명과 읽을 수 있는 본문을 우선합니다.[2] PageSpeed/Lighthouse의 좋은 점수는 순위 보장이 아니며, 로컬 실험 점수와 실제 공개 주소·실사용 Core Web Vitals는 별개입니다.[12]

현재 noindex 상태에서 Lighthouse SEO가 감점되는 것은 의도한 공개 정책의 결과입니다. 점수만 높이려고 noindex를 지우거나 검사에서 빼지 않습니다.[13] `llms.txt`는 보조 설명으로 유지하지만, Google은 AI 검색 노출을 위한 별도 AI 텍스트 파일이 필요하지 않다고 안내합니다.[14]
