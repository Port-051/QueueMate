기준일 2026-10-13. 이 문서는 **사용자가 보는 흐름마다 "무엇으로 확인하는가"** 를 적은 지도다. 항목은 이 앱의 규칙(`frontend/CLAUDE.md` §3 소유자 결정 1~46 · `platform/contracts/platform-api.md` P-1~57 · `mentor-room-ux.md`)에서 뽑았고,
묶음과 관점(기능 · 이동 · 폼/검증 · 인증/세션 · 실시간 · 오류 상태 · 접근성 기본 · 반응형)은 일반 웹 앱 QA 체크리스트의 뼈대를 빌렸다 —
[Marker.io "The Ultimate Website QA Checklist"](https://marker.io/blog/website-qa-checklist) · [BrowserStack "Website QA Testing"](https://www.browserstack.com/guide/how-to-perform-website-qa-testing) · [F22 Labs "Web Application Testing Checklist"](https://www.f22labs.com/blogs/web-application-testing-checklist-for-beginners/)(뼈대만 — 항목은 전부 이 앱의 것이다).

## 코드를 읽고 의심한 것(실행으로 확인하지 않았다 — 메인 세션에 보고)

1. **네트워크가 끊긴 채 SSE 재시도가 실패하면 로그아웃 상태로 떨어질 수 있다** — `src/api/http.ts` `refreshSession()` 의 `catch` 가 모든 실패(네트워크 오류 포함)에 `onAuthLost()` 를 부르고, `src/api/sse.ts` 는 `EventSource` 가 CLOSED 가 되면 `refreshSession()` 을 부른다. 오프라인에서 재시도가 네트워크 오류로 CLOSED 가 되면 재발급 `fetch` 도 실패 → 익명 → `/login`. 쿠키는 살아 있어 새로 고치면 다시 로그인돼 있을 것이다. 시나리오 22 는 이 갈래를 피하려고 재발급 요청만 200 으로 받는다.
2. **글 지우기 버튼이 화면에 없다** — `CLAUDE.md` §3-31 은 방 화면에 "글 지우기" 하나가 남는다고 적었지만 2026-10-02 팀 UI("시각 정리 및 메뉴 제거")가 방 메뉴째 없앴다(`PartyRoomPage` 에 `deletePost` 호출이 없다). 모집 중인 방장이 글을 거두는 길은 "방 나가기"(방이 닫히고 글이 만료)뿐이다 — 결과는 같아 기능 공백은 아니다. 문서와 어긋난다.
3. **세션 확인이 끝나는 순간 앱이 통째로 다시 마운트돼 그 전에 채운 입력이 지워진다** — `src/main.tsx` 가 `<App/>` 을 `MatchProvider` · `SocialProvider` 아래에 두고 둘은 `key={status:userId}` 라, `GET /users/me` 가 끝나 `loading → anonymous` 가 되면 라우트 전체가 다시 마운트된다. 2026-10-13 첫 실행에서 개발용 로그인 입력(`e2e-a`)이 기본값 `dev-tester` 로 되돌아가 **소유자의 손 테스트 계정으로 로그인됐다**(시나리오 24 는 세션 확인을 기다린 뒤 채우고 본문이 `e2e-a` 가 아니면 요청을 끊는다). 운영에서는 소셜 버튼만 있어 사용자 입력이 없지만 소셜 가입 폼(`/signup/social`)도 같은 처지일 수 있다 — 제품 개선 후보(미검증).
4. **확정 · 끝남 글자가 카드에 없다** — §3-34 의 "확정 · n명" / "끝남 · n명" 머리 글자는 팀 UI 가 상태 배지를 걷어 보이지 않는다(`POST_STATUS_LABEL` · `POST_ENDED_LABEL` 은 남아 있고 쓰는 곳이 없다). 참가 버튼의 접근성 이름(`마감 · 끝난 파티예요`)으로만 가른다.
